## 目的

用 [V2.1 回歸測試集](benchmark-v2.1.md)替 0.2.2 建立基準，之後用同樣方式比較 0.3.0。

| 項目 | 設定 |

| Skill | 帳號同步安裝的 personal-memory **0.2.2**；子代理在技能清單中只看到 `description`，需要時自行載入 |

## 觀察

- **唯一漏掉的是隱性題 M07。** 問題沒有「我以前」「當初」這類字，只說「幫部落格加留言功能」。0.2.2 的 `description` 只列了明示說法，這正是 0.3.0 Retrieval Gate 要補的情況。其他三題隱性題（M08–M10）有觸發，可能因為「雲端費用」「Agent Wiki」「工作上」這類字讓 Agent 聯想到使用者自己的專案。
- **Claude Code 子代理的觸發遠比 claude.ai 一般對話穩定。** [Skill 0.2.0 回饋](skill-0.2.0-review.md)中，claude.ai 只裝外掛程式時 Skill 從未被觸發。本輪同樣只靠技能清單的 `description`，18 題觸發 17 題。觸發問題看起來和平台的 Skill 載入機制有關，不只是 `description` 措辭。這點要在 claude.ai 上跑同一組題目才能確認。
- 每題固定先搜「Personal Brain Lab」找根頁面，再搜主題，大多 2 次 search 加 1～3 次 fetch。找不到的題目會換 3～4 組關鍵字，符合 `retrieve.md`。
- 每題延遲約 20～50 秒（子代理整體執行時間，含載入 Skill 與工具），不需要記憶的題目約 3～20 秒。

## 限制

- 只跑一次，只測 Claude Code 子代理，不代表 claude.ai、ChatGPT、Codex 的表現。
- 子代理收到的是主 session 轉交的任務，知道自己在受測。題目後附的「請勿讀取工作目錄」可能讓它更謹慎，但沒有提到 Notion 或記憶。
- 工具紀錄由子代理自行回報，主 session 沒有逐筆核對原始工具呼叫。28 題都回報沒有讀取工作目錄。
- 「正確」由主 session 依子代理回答與 Personal Brain 頁面內容判讀，部分題目只做抽查。
- M19、M20（寫入與修正）未測，錯誤保存指標沒有數據。
