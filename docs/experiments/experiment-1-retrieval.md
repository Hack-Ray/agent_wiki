# Experiment 1: Memory Retrieval

## 目的

驗證 AI 只靠官方 Notion connector，能否用自然語言找回 `Personal Brain Lab` 中的記憶。

驗收標準：10 題中至少 8 題正確（V2 規格第 10 節）。

## 測試資料

Notion 根頁面 `Personal Brain Lab` 下目前有 7 個子頁：

| 頁面 | 性質 |
|---|---|
| 00 — About This Brain | 使用說明，非題目來源 |
| Agent Wiki 架構反思 | 真實，含 2026-09 V1 觀點與 2026-10-31 V2 修正 |
| 學習方式反思 | 🧪 虛構 |
| 未解假設：API 偶發變慢 | 🧪 虛構，未證實的推測 |
| Docker 映像檔瘦身經驗 | 🧪 虛構 |
| Git 工作流程偏好 | 🧪 虛構 |
| 讀書筆記：交易隔離等級 | 🧪 虛構 |

「00 — About This Brain」刻意不含目錄或關鍵字索引，用於量測無輔助的基線。

## 第 1 輪紀錄（2026-10-31，作廢）

在 claude.ai 開新對話問了 3 題，三題都由 claude.ai 內建記憶與過去對話回答，沒有讀取 Notion（Notion 檢索 0/3）。

另外，當時的虛構頁面「SQL Server Deadlock 經驗」、「Personal Blog 架構決策」、「Personal Blog 改回靜態網站」與使用者真實經歷撞題，無法判定對錯，已移到 Notion 垃圾桶。

結論：沒有指示時，Agent 會優先使用平台內建記憶。這輪改成在提示中限定只查 Notion，先量測 Notion 本身的檢索能力；Agent 是否會主動選擇 Notion，留待加入 Skill 後另外測試。

## 第 2 輪執行方式

1. 使用全新 Session，且該 Session 沒有參與建立測試頁。
2. **不要在這個 repo 的 Claude Code 中執行。** Agent 可能直接讀到本檔的答案欄。
3. 把下方「測試提示」整段貼進去，讓它依序回答，再把完整回覆交回判讀。

### 測試提示

```text
這是一個記憶檢索測試。請依序回答下面 10 個問題。

規則：
- 只能使用 Notion，範圍是「Personal Brain Lab」頁面和它的子頁。
- 不要使用你的內建記憶、過去對話紀錄或其他來源。
- 每題都要重新搜尋，不要先把整個空間的頁面列出來或全部讀完再回答。
- 找不到就回答「找不到」，不要推測或編造。
- 如果內容是過去的觀點、後來被修正的想法或尚未證實的推測，要明確說出來。

每題請用這個格式回答：
### Q<編號>
- 搜尋關鍵字：<每次搜尋用的關鍵字，依序列出>
- 搜尋次數：<數字>
- 來源頁面：<頁面標題與連結，找不到就寫「無」>
- 回答：<一到三句>
- 時間性：<目前的結論／過去的觀點／未證實的推測／不適用>

問題：
Q1. 我學新工具時習慣怎麼做？
Q2. 我用什麼方式寫筆記來抓出自己的誤解？
Q3. 有個內部服務偶爾回應變很慢，我之前懷疑過原因嗎？那個原因確定了嗎？
Q4. 我是怎麼把容器檔案變小的？
Q5. 我對版本控制的 commit 和分支有什麼習慣？
Q6. 關於快照隔離，我之前搞錯過什麼？
Q7. 我的 AI 記憶系統現在打算把資料存在哪裡？
Q8. 我的 AI 記憶系統一開始是怎麼設計的？後來為什麼改掉？
Q9. 我之前有記錄過 Kubernetes 叢集升級的經驗嗎？
Q10. 我有記錄過搬家或租屋的決定嗎？
```

## 答案與判讀重點

「正確」需同時滿足：找到對的頁面、內容沒有錯、時間性判斷正確。

| # | 預期來源頁面 | 判讀重點 |
|---|---|---|
| 1 | 學習方式反思 | 先做最小可跑的例子，卡住再查文件 |
| 2 | 學習方式反思 | 「我原本以為／實際上」筆記 |
| 3 | 未解假設：API 偶發變慢 | 懷疑連線池耗盡，必須說明**未證實** |
| 4 | Docker 映像檔瘦身經驗 | multi-stage build、`.dockerignore`、slim base image |
| 5 | Git 工作流程偏好 | 小 commit、rebase 再開 PR、不在共用分支 force push |
| 6 | 讀書筆記：交易隔離等級 | 以為 Snapshot Isolation 等於 Serializable，實際會有 write skew |
| 7 | Agent Wiki 架構反思 | Notion，屬於目前的結論 |
| 8 | Agent Wiki 架構反思 | V1 為本機 SQLite + FTS5 + lifecycle，屬於過去的觀點；改掉是因為手機與跨 AI 用不了、操作成本高 |
| 9 | 無 | 必須回答找不到。根頁面殘留一行「SQL Server Deadlock 經驗」文字，不應被當成相關紀錄 |
| 10 | 無 | 必須回答找不到 |

### 第 2 輪限制

- 題目由建立頁面的 Agent 撰寫，用詞與頁面原文重疊（例如「學新工具」、「誤解」、「快照隔離」），換句話說的難度偏低。「Notion 搜尋偏關鍵字比對」的疑慮沒有被證實，也沒有被排除。
- 只有 7 頁資料，頁面數量增加後的排序品質未知。
- 提示明確限定只查 Notion，量不到 Agent 會不會主動選擇 Notion。

## 結果判讀

- 8 題以上正確：Notion 檢索基線通過。下一步測試加入 Skill 後，Agent 在沒有限定來源的提示下是否會主動查 Notion。
- 未通過：先不寫程式。依序嘗試在「00 — About This Brain」加入目錄與關鍵字，或在 Skill 中要求 Agent 換多組關鍵字重查，再重跑本實驗比較差異。
